## Private planning contract

Keep legacy cohort/catalog/inventory/request hashes exact. A separate versioned compatibility descriptor includes namespace, exact request/tool policy, chosen callback, relevant client/resource definitions, current-principal and all-principals grants for both request stages, grant visibility/query identity and collector semantics. A display-name change may alter exact input pins without invalidating compatibility. Reuse refers to original source/record IDs and observation dates; nothing is relabeled as newly collected. Full input/history validation precedes selection.

Private requests come from approved Goal 3 named-tool requirements and strict profiles, with current inventory and typed saved evidence. Public weekly selections are a separate contract. Deterministic order is tool-critical relevant changes, missing evidence, bounded unresolved attempts, overdue refresh, exploration; reserve a bounded fairness share. Catalog metadata has a 24-hour target, tool-critical private planning evidence is at most 24 hours old, and broader public assessment defaults to seven days; stable failure cooldown starts at 24 hours and backs off to seven days, reset by relevant change. Unknown/failed/latest attempts retain earlier success but cannot establish current successful authorization. No saved token is trusted as an acquisition credential.

Use explicit global counters for issuance/retries/bootstrap/inventory/pages/source/other HTTP and elapsed time. Persist intent before dispatch, keep uncertain consumption charged, persist terminal evidence before completion and permit at most one explicitly requested recovery retry of a supported non-mutating operation. Recognized transient retries are capped at three within the global budget. Sign-in, registration, consent, publication and other mutations never retry automatically. Projection/export retries consume saved evidence only. Existing legacy resume identities remain unchanged.

## Offline commands and operator boundary

`Get-TokenForgeRefreshPlan -InputJson $json -AsOf $instant` and `tokenforge refresh plan --input-path input.json --as-of <instant> --json` share the same core. The input contains the strict profile, named requirements, complete frozen inventory and typed snapshot, exact pins, explicit policy and original refresh history. Start history with `AdminWorkflows.CreateRefreshHistory()` and policy with `CreateRefreshPolicy(requirementsJson)`. The repository's `tests/fixtures/refresh/RefreshFixture.ps1` is a synthetic example, never a source of live identities or provenance. Exit 0 means all declared work is fresh with no reported miss; exit 3 means observation/work or review is needed; malformed native input exits 1, consistent with the existing native command error contract. A plan never establishes authorization.

`tokenforge refresh validate`, `capture`, `status` and `project` and the PowerShell saved-evidence adapters do not authenticate. Status/project require an existing protected journal. History retains original snapshots, individual observation references and empty denied/incomplete/not-collected coverage witnesses. Latest issuance and API observations are chosen separately across all compatible history, with individual future observations excluded at evaluation time and equal-time contradictions treated as unknown. `ReuseOrigins` retains the exact original identities and references for independently collected phases.

Actual acquisition is an explicit separate operation: `Invoke-TokenForgeRefresh -PlanJson $plan -AccountStateDirectory <stable-private-account-directory> -EstsAuth <existing-SecureString>`. The optional declared API proof also requires `-OperationCheck`; declaring a tool requirement alone does not approve that API call. The mandatory bootstrap identity GET remains part of strict account confirmation. No credential lookup, sign-in, renewal, registration, consent, fallback client or publication happens automatically. It revalidates every returned token with Goal 3 policy. The mandatory bootstrap identity GET is counted separately from bootstrap OAuth exchanges. This command is implemented but no live Goal 4 invocation is authorized or claimed here.

The production adapter always derives `refresh-run.json` within the explicitly selected account directory, protected by an account-store lock and namespace marker. Changing evaluation time or a per-plan filename cannot reset an unresolved run. `Move-TokenForgeRefreshPlan` explicitly advances a run only when every started request has a durable terminal snapshot, old namespace matches and exact prior history is retained. Never-started pending requests may move to the next explicit plan. Old primary state is archived before atomic canonical replacement. Missing canonical state with an existing marker fails closed. Keep one stable directory per account; this is a storage boundary, not an OS-wide registry across arbitrarily selected directories. There is no force/reset shortcut for unknown remote consumption. Unknown issuance is retained for review; explicit single-operation recovery is limited to supported read-only GETs, never a sign-in or mutation. A new session is always separately supplied by the operator.

Selection budgets of at least two requests reserve at least one lower-priority fairness seat (rounding the configured percentage up to one request); Zero and single-request budgets reserve none; single-request plans keep the highest priority and make progress within the finite frozen cohort as that work completes or is deferred. Lower-tier work uses oldest observation then stable request identity, rather than a calendar-modulo rotation. This provides service within a finite frozen cohort as selected work becomes fresh, enters cooldown or reaches its explicit unresolved-attempt bound. It does not promise fairness while replacing the cohort with an unbounded stream of new requests. Public weekly queues use a separate seven-day broader-assessment default and one bounded lower-tier seat. Every Prepare writes a current freshness-status bundle, including frozen/no-work resumes, without changing the recorded recipe. Catalog metadata collection has a separate 24-hour target; aggregation time alone does not prove a download, and resource permission definitions remain explicitly NotCollected unless separately collected. Manual cadence does not guarantee daily freshness. Legacy frozen selections retain their recorded policy and exact hashes on resume.

Pins are caller-attested, content-shaped provenance, never a signature or remote permission grant. Frozen input replay validates the entire plan, historical snapshots, context/namespace links, descriptors, original evidence and selection arithmetic before capture or execution. A local package receipt independently ties tested source and payload hashes to the built runtime. Private journals use restrictive files/directories, exclusive writers, flushed temporary files and atomic renames. Guarantees cover tested process termination, not filesystem directory durability after a power failure.

`Measure-TokenForgeRefresh.ps1` validates the same complete frozen synthetic input for replay and incremental paths, counts synthetic dispatches and retained context facts, and records local validation/planning/projection time and memory. Source/inventory/network/database stages absent from this in-memory benchmark are reported as zero, not fabricated measurements. It makes no network latency or production CPU improvement claim. Request avoidance and local overhead are reported separately.
