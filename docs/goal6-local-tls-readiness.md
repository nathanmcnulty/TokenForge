## Implemented transport

`TokenForgeLocalTlsTransport.mjs` executes actual Node HTTPS requests, with a new private agent and connection for every charged exchange. Physical routing is hardcoded to IPv4 loopback, an ephemeral fixture port and `tokenforge.fixture.invalid` SNI. Only the explicit fixture CA is trusted for this client; normal hostname/chain checks and TLS 1.3 remain enabled. No system trust, security setting or dependency is changed. The selected existing Linux x64 Node 24.18.1 executable must match SHA-256 `f3432a45b03b2da0d270095fdd8813dc34cbea73f5fc8b18c7a384b7cf9b333a` before a transport handle can be created. This local pin does not attest a hosted runner binary.

The logical protocol still uses fixed reserved fixture origins and exact dummy capabilities. The client sends literal synthetic Runtime and Read bearer values to their distinct slots; Blob and Download carry no bearer. Logical Host/path/query octets are independently checked by the local backend. No caller-supplied transport callbacks, credential reader, real hostname, proxy, redirect-following or resend path exists. A clear-environment child with Node's environment-proxy option enabled verifies the explicit agent bypasses inherited proxy selection. Each mutation is attempted once, even when the server received it but the acknowledgement was lost.

Requests are asynchronous. The transaction busy flag and exclusive private-store lock remain held until request and socket close. Explicit cancellation aborts the handle permanently. The per-exchange wall/monotonic deadlines are fixed at entry and capped by the journal's unchanged total deadlines. Setup time reduces remaining time; completion rechecks both exchange deadlines even if timer delivery was delayed. The core additionally checks after response parsing before acknowledging. Linux event-loop/timer scheduling is not a real-time guarantee: a stalled process can abort late, but cannot accept a late response as an acknowledgement.

Headers are limited to 16 KiB, 64 fields and 4096 characters per value, with duplicate fields, ambiguous transfer/content lengths, trailers, unsupported encodings, partial bodies and redirects refused. Bounded diagnostics (`date`, connection/server/cache fields, GitHub/rate-limit/Azure IDs and access-control fields) are explicitly projected out and confer no authority. Selected content/redirect/pagination fields remain subject to protocol validation. HTTP chunk framing is decoded without changing entity bytes. Twirp aliases stay strict; bounded complete duplicate-free REST JSON requires identity fields but permits non-authoritative extra fields. This profile is source-informed, not a captured real-service compatibility assertion.

The fixed transaction limits remain 64 KiB C, four mutations/eight reads/twelve attempts, 180 seconds, ten seconds per exchange, 8 KiB control requests, 128 KiB control responses and 2 MiB aggregate reserved request/response entity bodies. Reservations are persisted before dispatch and never refunded. Header caps are separate. Entity bytes delivered in the chunk that crosses a cap may exceed that cap before abort; TLS/TCP/kernel/framing bytes are not charged by the entity budget. Transcripts record observed entity byte counts and hashes, never bodies, URLs, queries, headers, credentials or raw exceptions.

## Evidence and recovery

Original C remains unchanged in the saved file, Block body and observed Download. The independent fixture backend does not use the production protocol serializer/validator to generate or validate its wire payloads. Synthetic local evidence covers fresh connections, TLS failures, connection refusal, dropped acknowledgements at all four mutations, malformed/oversized/partial responses, cancellation, header/body/handshake stalls, redirects, proxy isolation and role separation. It does not prove Azure/GitHub preservation of C or service-side mutation semantics.

Journal v3 binds exact engine/profile hashes, runtime binary and fixture CA/port authority. Old journals refuse without migration or rewriting. Fake handles require the same branded clock; local TLS accepts only real Linux timing. Same-store resume preserves deadlines, charges and unknown barriers. Stale locks after process death still refuse automatic takeover. There is no cross-job recovery or power-loss claim.

Artifact metadata retains an optional observed `expires_at`, fixes its value on the first observation and rejects changes or expiry after parsing and before `Observed`. A final Run response cannot extend that validity. Missing expiry remains explicitly unobserved (`null`), never an inferred retention guarantee. If a completed observation's known expiry later passes, subsequent results say `SavedObservationExpired` without rewriting its historical journal or redispatching. Artifact-own attempt and workflow ID remain unobserved; separate Run reads do not supply those fields. Privacy/business-schema approval and operational emission remain false.

## Dormant service and controller

`createServiceTransport`, the local JavaScript action and the controller CLI fail unconditionally before consulting arguments, environment or credentials. Public-context and Azure capability checks are pure design validators with no execution authority. Even a matching synthetic context returns `selectedRunnerProven=false`, `credentialAccessAllowed=false` and `serviceExecutionAllowed=false`.

The future profile proposes Results, GitHub REST and Azure blob origins/API versions in `TokenForgeCanaryPreflight.mjs`. Capability shape checks reject duplicate/encoded/extra operation keys, excessive/expired dates, wrong role/permissions, non-HTTPS origins and partial/incoherent delegation keys. They preserve the input string, do not authenticate its issuer, and are not wired to the loopback-only dispatcher. Real Results origin/backend IDs, issuer scopes, runner source/runtime and complete real responses remain unverified. No fallback expands this allowlist automatically.

The controller exposes only a bounded nonexecutable procedure and restore plan. It requires exclusive custody, exact repository/workflow IDs, unchanged permission-policy fields and equality to the last applied state. It only proposes restoring original enablement bits. No compare-and-swap support is claimed for GitHub Actions APIs; simultaneous writers require enforceable exclusive administrative custody. If that cannot be established, hosted activation remains blocked. No controller HTTP implementation or dispatch path is present.

The manual-only workflow template is stored outside `.github/workflows`, has a literal-false job condition, pins checkout and the implementation source, and calls the unconditionally blocked action. Existing active workflow files and Actions settings are unchanged. The canary decision packet describes a later separately reviewed activation change; the current checkpoint is not runnable against a service.
