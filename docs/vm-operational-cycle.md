# Frozen Linux collector cycle

The supported offline-v1 operational entry point is the existing budgeted discovery runner with `-FrozenCycle`. It retains the newer collector's primary-evidence recovery, account verification, request ceilings, pause/unknown classifications and exact cohort contract. This reconciles draft #117 without introducing a second collector or copying its older unbudgeted implementation. Actual authenticated VM, reboot and scheduling acceptance in #115 remains open.

Run the wrapper from a complete reviewed Linux x64 package, using PowerShell 7.6+ on .NET 10. Retain its manifest digest and exact source revision independently. The mode verifies every listed payload hash and size, refuses extra members and links, and requires the running wrapper/module and native executable in the same package. The expected pins must come from the reviewed qualification result, rather than being calculated anew at each launch. A trusted digest detects substitution; it is not a signature or authorization. The verification assumes the package directory remains protected from concurrent mutation throughout execution.

```powershell
& /trusted/package/scripts/Invoke-TokenForgeDiscoveryRun.ps1 `
  -FrozenCycle -StatePath /private/tokenforge/account `
  -NativeExecutablePath /trusted/package/tokenforge `
  -PackageManifestPath /trusted/package/public-health-package.json `
  -PackageManifestSha256 $reviewedManifestSha256 `
  -PackageSourceRevision $reviewedSourceRevision `
  -EstsAuth $existingSession -SessionExpiresAt $declaredSessionDeadline `
  -MaxChunks 1 -MaxMinutes 15 -MaxIssuanceAttempts 30 -MaxTotalRequests 300
```

The session is supplied in memory as an existing SecureString. Acquisition in this example requires separate explicit authorization; the offline milestone does not execute it. No credential source, sign-in, renewal, consent, registration, session provider, service installation or scheduler is invoked. Keep credentials out of command-line text, environment variables, logs and receipts. The wrapper copies and disposes its own SecureString while retaining the caller's original.

Before acquisition the mode requires existing private state, `discovery-run.json`, `inventory.json` and `discovery.json`. It rejects `NewRun`, `RefreshDiscovery` and `RefreshInventory`. Missing inventory, a capture older than 24 hours or over five minutes in the future requires operator review; the mode never updates a timestamp, downloads metadata or refreshes an inventory. Account/recipe checks still reject changed frozen inputs. Inventory refresh and any new cohort belong to a separately reviewed operation; preserve the prior cohort and original evidence.

The existing `.discovery.lock` excludes competing wrappers and the collector retains its `.writer.lock`. Each invocation has finite request/deadline/retry ceilings including bootstrap and identity verification. The existing bounded bootstrap verifies the session's account through the fixed Graph identity GET before using saved inventory. It consumes its declared budget even though source and inventory collection are disabled in this mode. Keep invocation receipts when allocating one approved aggregate envelope over multiple invocations; a restart does not grant new authorization.

The declared expiry is an operator safety bound, not a guarantee of service acceptance. Expiry and a private `stop.requested` marker are checked through the existing budget path before dispatch and during retry waits. Transport cancellation is bounded by the earlier operation deadline, session deadline and timeout. Stop-marker observation is cooperative; an in-flight operation can finish before the next boundary. Actual service expiry is classified by the newer collector as paused/unknown/request-blocked according to its evidence, rather than an unbounded sweep of failed cells. No automatic renewal follows.

Under the same lock, `vm-cycle.json` is written privately by flushed temporary file and atomic replacement before acquisition and after the result. It records package/source pins, cycle/cohort identity, timestamps, sanitized status/counts and the invocation budget. It always says `Publication: NotAttempted`. This is the latest cycle receipt, not an audit ledger or heartbeat. A retained `Running` receipt proves only the last durable write; use the OS lock and offline collector status to distinguish a live process. After termination, restart only following offline inspection and a separately valid session/authorization. Completed evidence is skipped, while uncertain external consumption remains unknown and needs explicit bounded recovery. `ResumePaused` and `RecoverUnknown` are never added automatically.

Terminal `Complete` and `StructurallyExcluded` cycles exit 0 and preserve that status in both returned JSON and `vm-cycle.json`. Structural exclusion means the selected pairs require no issuance; it is not a token success or authorization claim. Every unfinished, blocked or failed result exits 1 and provides typed JSON. `InFlightUnknown` takes precedence over either terminal result whenever consumption remains uncertain. An expiry test harness may exit 0 after confirming the runner's expected `SessionExpired` exit 1; those are separate process outcomes. `BudgetReached` needs review of its budget reason; `SessionExpired`, `Cancelled`, `Paused`, `InFlightUnknown`, `AccountMismatch` and other failures are operator stops. Do not use unconditional restart policies. If receipt persistence fails, the runner reports failure; authoritative checkpoints and older receipts remain. A receipt cannot prove publication, projection completeness or backup. Use the existing offline collector status command and SQLite-aware backup tooling independently.

Export the saved cohort through the existing seven-file candidate API, then use independent approval and the separate publication verifier/writer contracts. Collection completion grants no publication authority. Failed export/publication can be retried from saved evidence without collection; no cycle code invokes publication or backs up databases implicitly.

Offline fixtures cover package/source/payload refusal, missing/stale/future inputs, exclusive locks, sanitized durable receipts, same frozen cohort and budget forwarding, session deadline/retry/transport cancellation, stop markers and typed pause/unknown/account failures. Existing collector kill/restart and native checkpoint fixtures remain their own evidence, with original revisions and limits. These synthetic checks do not establish authenticated VM/reboot behavior. Before closing #115's operational acceptance, separately authorize and record a small real-VM cohort, actual lock exclusion, durable-evidence/checkpoint/projection interruptions, measured cancellation overrun, declared and service-side expiry, same-account renewal/different-account refusal, and reviewed saved-evidence publication/retry. Timer activation, protected reboot-time session loading and reboot proof require their own approval. No such execution is authorized here.
