# TokenForge sign-in audit OIDC claim proof

This phase prepares a manually dispatched GitHub claim check for the exact TokenForge repository. The job uses trusted default-branch source and only `contents: read` and `id-token: write`. It requests an assertion from GitHub's HTTPS identity provider, checks it in memory, and prints boolean claim matches only. It takes no dispatch inputs or Entra credentials, makes no Entra token exchange or Graph request, and publishes no artifacts or issue content. [GitHub OIDC claims](https://docs.github.com/en/actions/reference/security/oidc#immutable-subject-claims)

Before dispatch, verify that `entra-audit` has **Selected branches and tags** with one literal branch, `main`, no tags, and no secrets or variables. Keep the existing repository-wide OIDC subject configuration. The environment restriction controls which refs can get jobs into the environment. A separate main-only branch rule should require pull requests with zero required approvals, block force pushes and deletion, and have no bypass. Confirm the current rule state and the independently reviewed workflow before any dispatch. This phase does not apply the rule or dispatch the workflow. [GitHub deployment environments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments) · [GitHub rulesets](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets)
