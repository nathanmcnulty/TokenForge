# Directory provisioning discovery

This source-only candidate adds a distinct bounded directory-audit phase alongside sign-in collection. Microsoft Graph v1.0 supports `GET /auditLogs/directoryAudits` filtered to `Add service principal`, with `AuditLog.Read.All` as the least application and delegated permission. The prototype checks UTC half-open day windows and exact Graph continuations. The workload can reuse the fixed no-redirect transport only after independent review of the AppId evidence and workflow. [Microsoft Graph directory audits](https://learn.microsoft.com/en-us/graph/api/directoryaudit-list?view=graph-rest-1.0) · [Microsoft Entra provisioning evidence](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/howto-view-service-principal-creation-with-audit-log-properties)

Microsoft documents service-principal provisioning and owner clues. A bounded read-only sample corroborated one successful provisioning event by comparing the scalar `additionalDetails.AppId` value with an independently known client AppId. The parser accepts the exact case-sensitive key `AppId` only with one such scalar and a sole service-principal target with a canonical nonzero object ID. The object ID is only a structural check. Extra targets, missing or duplicate case-insensitive keys, arrays, untyped values, and malformed targets remain unresolved. This sample does not establish a general guarantee that every provider event has the field. Values of owner and provisioning clues, raw rows, initiators and target object IDs are discarded. The target resource ID identifies an object, and the initiating AppId describes the actor. Neither can supply the provisioned client AppId. The new reader remains separate from the workflow until independently reviewed. [Graph audit target shape](https://learn.microsoft.com/en-us/graph/api/resources/targetresource?view=graph-rest-1.0)

The attended companion can replay a caller-minimized private JSON file with format `TokenForgeAttendedTargetAppIdEvidenceV1` and rows with exactly `targetAppId`, `audiences`, and `localManagedIdentity`. Use this only when the target client AppId and optional audience or managed-identity evidence were independently established through a trustworthy supported source. The adapter does not authenticate the caller's evidence or supply provider retention coverage. Use an empty audience list when evidence is unavailable. Set the local managed-identity flag only with explicit supporting evidence. A trusted `AzureADMyOrg` audience is excluded. Conflicting or missing audience evidence is kept as unknown. Owner identity and provisioning clues never prove publisher or account audience. JWT audience is outside this report.

The companion reads both catalog partitions from the exact Git commit and emits a private candidate-only result. The shared replay function accepts previously observed client AppIds for cross-source deduplication. The future issue writer accepts the resulting fixed provenance labels. There is no catalog write, public issue update, authentication, or live Graph action in this replay companion.

```sh
python3 -B examples/signin-review/directory_provisioning.py <normalized-evidence.json> <catalog-repository> <exact-catalog-commit>
```
