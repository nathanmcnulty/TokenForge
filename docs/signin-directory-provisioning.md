# Directory provisioning discovery

This source-only candidate adds a distinct bounded directory-audit phase alongside sign-in collection. Microsoft Graph v1.0 supports `GET /auditLogs/directoryAudits` filtered to `Add service principal`, with `AuditLog.Read.All` as the least application and delegated permission. The prototype checks UTC half-open day windows and exact Graph continuations. The workload can reuse the fixed no-redirect transport only after an independent review of the AppId mapping and workflow. [Microsoft Graph directory audits](https://learn.microsoft.com/en-us/graph/api/directoryaudit-list?view=graph-rest-1.0) · [Microsoft Entra provisioning evidence](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/howto-view-service-principal-creation-with-audit-log-properties)

Microsoft documents service-principal provisioning and owner clues. Microsoft Graph documentation does not establish a dedicated target client AppId field for this activity in the response shape reviewed here. The phase counts successful events with unresolved AppIds and tracks ambiguous principal targets and presence of documented clues. Values, raw rows, initiators and target object IDs are discarded. The target resource ID identifies an object, and the initiating AppId describes the actor. Neither is accepted as the provisioned client AppId. No application is admitted to automatic CI from this phase while mapping is unproven. [Graph audit target shape](https://learn.microsoft.com/en-us/graph/api/resources/targetresource?view=graph-rest-1.0)

The attended companion can replay a caller-minimized private JSON file with format `TokenForgeAttendedTargetAppIdEvidenceV1` and rows with exactly `targetAppId`, `audiences`, and `localManagedIdentity`. Use this only when the target client AppId and optional audience or managed-identity evidence were independently established through a trustworthy supported source. The adapter does not authenticate the caller's evidence or supply provider retention coverage. Use an empty audience list when evidence is unavailable. Set the local managed-identity flag only with explicit supporting evidence. A trusted `AzureADMyOrg` audience is excluded. Conflicting or missing audience evidence is kept as unknown. Owner identity and provisioning clues never prove publisher or account audience. JWT audience is outside this report.

The companion reads both catalog partitions from the exact Git commit and emits a private candidate-only result. The shared replay function accepts previously observed client AppIds for cross-source deduplication. The future issue writer accepts the resulting fixed provenance labels. There is no catalog write, public issue update, authentication, or live Graph action in this replay companion.

```sh
python3 -B examples/signin-review/directory_provisioning.py <normalized-evidence.json> <catalog-repository> <exact-catalog-commit>
```
