# Collect interactive and non-interactive Entra sign-ins

Run `scripts/Get-TokenForgeGraphSignInGaps.ps1` in an attended, dedicated PowerShell 7.6 process with the official `Microsoft.Graph.Authentication` module. The collector uses an existing Global process-scoped delegated session for the explicitly selected account and tenant. The session needs existing `AuditLog.Read.All`, a supported Entra role and the tenant must have the license required for Graph sign-in reports. The script does not connect or request consent. If the SDK calls for reauthentication, use the expected tenant and account and stop at any new permission prompt. Keep organizational auditing and required security controls in place. [Graph sign-in API](https://learn.microsoft.com/en-us/graph/api/signin-list?view=graph-rest-beta) · [Operator-owned sign-in](operator-signin-gap-sample.md)

On Linux, create a private local checkpoint directory with mode 0700. Point `$CatalogRepository` at a checkout that already has the full data commit and both catalog objects. Then choose a UTC interval within the tenant's retention period.

```powershell
& ./scripts/Get-TokenForgeGraphSignInGaps.ps1 `
    -TenantId $TenantId -Account $Account `
    -CatalogRepository $CatalogRepository -CatalogCommit $CatalogCommit `
    -Since $Since -Until $Until -CheckpointDirectory $CheckpointDirectory
```

Both categories use Graph beta with a separate explicit event-type filter. The default windows align to UTC days. Graph documents `ge` and `le` on `createdDateTime`. The aggregator excludes events at the requested upper boundary, so adjacent outputs are half-open. For a problematic window, pass just its bounds, select its category with `-EventType`, and use `-WindowHours 1`. Re-run the same bounds and window size to continue after an interruption. Completed window receipts are reused. An unfinished window starts from its initial request. When substituting hourly reports, use their disjoint windows in place of the original day in any downstream assembly. [Graph sign-in resource](https://learn.microsoft.com/en-us/graph/api/resources/signin?view=graph-rest-beta)

The collector follows a continuation even on a zero-row page and requires a successful terminal page. The script supplies only GETs to the fixed beta sign-in endpoint. It validates an absolute continuation before passing its unchanged path and query to the Global SDK as a relative URI. A changed response endpoint fails the window. The official SDK controls HTTP redirects, authentication refresh, and its own retry and timeout behavior. The application-level checks do not prevent a redirect already followed inside the SDK. Where transport-level origin enforcement is needed, use an approved environment that enforces it. The script retries 429 and 503 within its own bounds and honors a final `Retry-After`. If the required wait exceeds the configured limit, wait before resuming. A transport failure leaves the window unfinished. [Microsoft Graph paging](https://learn.microsoft.com/en-us/graph/paging) · [Throttling](https://learn.microsoft.com/en-us/graph/throttling)

Standard output is a minimized coverage ledger with separate statuses for completed, resumed, deferred and failed windows. Each completed receipt contains the existing aggregate in its `Aggregate` field. It stores only pending client AppIds and separately labeled observed resource IDs, counts, and times. Duplicate events are removed across pages within each window. The script keeps event IDs in memory for deduplication and retains neither raw events nor continuation URLs. Keep reports and the checkpoint directory private, and close the dedicated PowerShell process after the run. Full tenant history and JWT audience remain unknown. A sign-in record does not establish successful authentication or verify an app.

The beta `appOwnerTenantId` field can support a separate matched-window experiment with an exact Microsoft owner tenant filter. Use broad collection for inventory. Evaluate any filter in a separate run and compare counts, distinct AppIds, missing owner values and latency before making coverage claims. An owner indication can corroborate publisher evidence. The collector does not apply an owner filter. [Microsoft first-party verification](https://learn.microsoft.com/en-us/troubleshoot/entra/entra-id/governance/verify-first-party-apps-sign-in)
